Serralheria em São José dos Campos — estratégia do site

Documento interno (não publicar). Etapas 1 a 4: arquitetura, SEO, design system e wireframes. Stack: HTML, CSS e JavaScript puros — sem frameworks, sem build.

0. O que foi aproveitado da referência (eletricacampos.com.br)

  • Aproveitado: hub de serviços → hubs por categoria → páginas de serviço; navegação rastreável em HTML; CTA recorrente de orçamento; rodapé com mapa de links; blog ligado às páginas comerciais.
  • Não aproveitado: volume de páginas quase-duplicadas (ex.: instalação de tomadas + troca de tomadas), páginas de cidade/bairro por troca de nome, selos de credenciais e "atendimento 24h" sem prova, CTA de WhatsApp repetido 5+ vezes na home.
  • Diferença estrutural: lá os serviços são agrupados por segmento de cliente; aqui são agrupados por objeto fabricado (portão, estrutura, cobertura…), porque é assim que o cliente de serralheria formula o pedido ("preciso de um portão"), e o segmento (residencial/comercial) vira seção dentro da página.

1.2 Conflitos de canibalização a monitorar

  • /portoes/ x /portoes/portao-basculante/ para "portão de garagem": o hub foca em escolha de tipo; a basculante não usa "portão de garagem" no title.
  • /coberturas/ x /coberturas/cobertura-para-garagem/: "cobertura metálica para garagem" fica com a página de garagem; o hub linka com essa âncora.
  • /portao-industrial/ x /porta-de-enrolar-automatica/: industrial = vãos de galpão/portaria; porta de enrolar = fachada de loja. Ambas linkam uma para a outra com explicação.
  • /blog/portao-basculante-ou-de-correr/ x money pages: o artigo é comparativo e não tenta ranquear por "portão basculante"; linka as duas money pages.
  • /estruturas-metalicas/pergolado-metalico/ x /coberturas/: pergolado = estrutura vazada/decorativa; cobertura = proteção total contra chuva. Explicado nas duas.

1.4 Estruturas preparadas para o futuro (sem dados inventados)

  • Projetos: /projetos/_modelo-projeto.html (noindex) com campos: fotos, bairro, serviço, problema, solução, materiais, dimensões, duração, resultado. URL final: /projetos/{servico}-{bairro}/. Ao publicar o 1º projeto, remover o noindex de /projetos/.
  • Estudos de dados: /dados/_modelo-estudo.html + assets/js/estudo.js lê um JSON de orçamentos reais (tipo, largura, altura, material, automatização, faixa, prazo, região) e gera tabelas/medianas. Nenhum dado incluso.
  • Calculadora: /calculadora-portao/ já coleta as especificações e envia como pedido de orçamento. A função estimarPreco() em assets/js/calculadora.js retorna null até receber a tabela real.

  • Hub → todos os filhos (cards) + comparação entre filhos.

2. SEO on-page (Etapa 2)

Title, description, H1 e estrutura de H2/H3 estão implementados em cada arquivo HTML. Padrão de título: Serviço em São José dos Campos | Diferencial — a cidade aparece no title e no H1 das money pages, e no conteúdo só onde é natural (área atendida, clima, projetos).

Estrutura padrão de money page:

  1. H1 + resposta direta (o que é, para quem serve) — formato citável por IA
  2. Ficha técnica rápida (aplicação, materiais, acionamento)
  3. H2 Quando é a melhor escolha / quando não é
  4. H2 Tipos e variações (H3 por variação)
  5. H2 Comparação com a alternativa mais próxima (tabela)
  6. H2 O que define o orçamento (fatores, sem preços)
  7. H2 Como funciona: da medição à instalação
  8. H2 Manutenção e cuidados
  9. H2 Perguntas frequentes (visíveis, sem FAQPage schema)
  10. Relacionados + CTA com formulário pré-preenchido

Schema usado: LocalBusiness (home/contato/sobre — apenas campos preenchidos), BreadcrumbList (todas as internas), Service nas money pages, Article nos posts. Sem FAQ schema.

3. Design system (Etapa 3)

  • Conceito: "folha de fabricação" — o site se comporta como um desenho técnico: linhas finas, cotas, numeração de seções, anotações em fonte mono. Metal e precisão sem faíscas.
  • Cores: Grafite #0F1112 · Grafite 2 #191C1E · Aço #8B9298 · Off-white #F3F1EC · Papel 2 #E8E4DC · Cobre #C8642E (sobre escuro) / #A3491A (texto sobre claro, contraste ≥ 4.5:1).
  • Tipografia: Archivo variável (eixo de largura): títulos em 112–125% de largura, peso 650–800, entreletra negativa; corpo em 100%, 400. IBM Plex Mono 500 para rótulos, cotas e numeração.
  • Escala fluida: 14 · 16 · 18 · 22 · 28 · 36 · 48 · 64 · 88 px (via clamp()).
  • Grid: 12 colunas, máx. 1320px, margens 16px (mobile) / 32px / 48px.
  • Espaço: base 4px — 4, 8, 12, 16, 24, 32, 48, 64, 96, 128.
  • Botões: primário cobre (texto grafite), secundário contorno, link com seta. Altura mínima 48px.
  • Cards: sem sombra; borda fina + marcas de canto; hover desenha linha cobre.
  • Formulário: rótulos visíveis, campos 52px, teclado numérico para WhatsApp, validação acessível.
  • Motion: só transform/opacity, 200–600ms, desenho de traço no SVG do hero; tudo desativado com prefers-reduced-motion.

4. Wireframes (Etapa 4)

  • Home: Hero (H1, sub, CTA, desenho técnico) → faixa de fatos (sem números inventados) → Clusters (6 cards) → "O que você precisa fabricar?" (lista de necessidades) → Como trabalhamos (processo) → Comparações que ajudam a decidir → Área atendida → Blog/guia → CTA + formulário.
  • Hub: Hero → cards dos tipos → tabela comparativa entre tipos → materiais/acabamentos → orçamento → FAQ → CTA.
  • Money page: Breadcrumb → Hero com ficha técnica e desenho → Sumário lateral fixo (desktop) → Conteúdo → FAQ → Relacionados → CTA + formulário.
  • Projeto: Hero com foto → ficha (bairro, serviço, dimensões, duração) → problema → solução → materiais → galeria → serviço relacionado → CTA.
  • Blog: Breadcrumb → título, data, responsável → resposta curta → conteúdo → box do serviço relacionado → CTA.
  • Contato: Formulário em destaque (mobile primeiro) → canais diretos → área atendida.
  • Mobile: menu em tela cheia com clusters expandidos, barra fixa inferior discreta (Orçamento + WhatsApp) que aparece após o hero e some quando o formulário está visível.

5. Situação atual: projeto próprio (rank & rent)

  • Marca do site: Serralheria Campos — usada só como marca do projeto, não como razão social.
  • Não há empresa vinculada: o site não exibe CNPJ, razão social, endereço, telefone, e-mail, horário, equipe, avaliações, garantias nem projetos.
  • Canais de contato (WhatsApp, telefone, e-mail) ficam ocultos até serem definidos em assets/js/config.js.
  • O texto não afirma que o atendimento é exclusivo de São José dos Campos; a cidade aparece como local de atendimento.
  • JSON-LD da home usa Organization (nome, URL, área atendida). Quando houver empresa parceira real, pode-se migrar para LocalBusiness com dados verificáveis.

6. Antes de publicar

  1. Obrigatório: definir formEndpoint (ou whatsapp) em assets/js/config.js. Sem isso o formulário não entrega pedidos.
  2. Substituir https://www.seudominio.com.br pelo domínio real (HTML, sitemap.xml, robots.txt).
  3. Criar assets/img/og-default.jpg (1200×630).
  4. Enviar o sitemap.xml ao Google Search Console.
